**السؤال الأصلي (المالك):** «متجر اكسسوارات جوالي عليه طلبات كثير في سلة، وباقي المتاجر
صفر — هل الفرق بالسيو؟» **الجواب المُثبت بالبيانات: لا، ولا علاقة للطلبات بترافيك المنصة.**

**الأرقام (فُحصت من DB الإنتاج + لوحة شركاء سلة، 2026-07-31):**
- لوحة سلة (link id 1270023187): **عدد المشاهدات = 2**، معدل التحويل **0%**، الطلبات
  المؤكدة **0**، الأرباح **0 ر.س**. الطلبات: 6 (16/07 ملغي، 29/07 ×4، 31/07) كلها **قيد
  الانتظار**.
- `action_logs` لمتجر id=18 **بعمره كله**: 8 `view_store` (6 منها يونيو 20-21 بلا geo،
  و2 سعودية 3 و6 يوليو) + **2 `click_link`** + **1 `copy_coupon`**. الباقي كله بوتات
  US datacenter. **آخر لمسة بشرية = 6 يوليو** — أي قبل 5 من الـ6 طلبات بعشرة أيام+.
- تطابق حاسم: سلة تقول «مشاهدات 2» ونحن سجّلنا «2 click_link» — **العدّاد سليم**، وهذا
  يثبت أن كل ما أرسلناه وصل، وأنه ضئيل.

**الآلية:** سلة تنسب الطلب **بالكود** (GGQ7T، خصم 20% للعميل / عمولة 15%) لا بالنقرة فقط.
فأي طلب يستخدم الكود يُحتسب حتى لو الشاري ما مرّ على الموقع إطلاقاً. الكود **غير منشور**
على مواقع الكوبونات المجمِّعة (فُحص بالبحث) — فالانتشار خاص لا عام.

**التفسير الأرجح:** عميل واحد دخل 3 يوليو ونسخ الكود ثم صار يعيد الشراء (3 طلبات متطابقة
138.43 ر.س + واحد 975 ر.س = نمط مشترٍ متكرر/بائع صغير). البديل: المالك شارك الكود شخصياً
خارج المنصة. القيمة إذاً **LTV لعميل واحد**، لا حجم ترافيك.

**ليش باقي المتاجر صفر — السبب الحقيقي:** الترافيك السعودي البشري = **213 زيارة / 135
زائر فريد في 30 يوم** موزّعة على **48 متجراً ≈ 2.8 زائر/متجر/شهر**. عند هذا الحجم الطلب
**يانصيب لا أداء**. الدليل القاطع أن السيو ليس الفارق: **ديزاج** أخذ 5 نقرات و**قطرة عسل**
3 نقرات + 4 نسخ — كلاهما **تفوّق** على متجر الاكسسوارات (2 نقرة) في تفاعل المنصة وما صار
عليهما طلبات. الطلبات غير مرتبطة إحصائياً بترافيكنا.

**ثغرة قياس مكتشَفة:** `copy_coupon` يُسجَّل **فقط عند ضغط زر النسخ** — النسخ اليدوي
(تحديد النص + Ctrl+C) لا يُتتبَّع، فعدد النسخات الحقيقي ≥ المسجَّل. لكن `view_store`
يُسجَّل لكل عرض صفحة بغضّ النظر، فعدد **الزيارات** موثوق — وهو ما بنى عليه الاستنتاج.

**⛔ لا API للمسوّق — محسوم بالتحقّق (2026-08-01):** **سلة** توثّق Merchant API وApps وShipping وCheckout وEvents وOAuth فقط؛ نقطة `api.salla.dev/admin/v2/affiliates` **للتاجر** ليدير مسوّقيه (تحتاج توكن متجر + `marketing.read_write`) ولا تعطي المسوّق طلباته — و**لا تصدير أصلاً في لوحة المسوّق** — صُحّح ٢٠٢٦-٠٨-٢٤ بفحص المالك على الشاشة (كان مكتوباً هنا خطأً أنها تدعم التصدير). المسار الحيّ: **نسخ جدول الطلبات ولصقه** في «إدارة الحملات ← الطلبات وقيمة الكود» — بُني لهذا الغرض. **كودماب** بلا API ولا توثيق ولا تصدير معلن (تطبيق جوال ⇒ API خاص غير موثّق فقط). و**`affiliate_conversions` (migration_064) موجود بالقاعدة بأعمدة كاملة، صفر صفوف وصفر مراجع بالكود** — بُني لـAdmitad postback ولم يُوصَل. عُرضت ٣ مسارات للتعبئة (استيراد يدوي + أديمتاد تلقائي / سحب غير رسمي بالكوكيز / طلب API رسمي) و**المالك اختار «لا شي»** — لا يُبنى شيء حتى يطلب. لا تُعِد البحث؛ ولا تقترح السحب غير الرسمي (يعرّض حسابي الدخل للإيقاف).

يتقاطع مع [[marketing_baseline_and_strategy]] (العنق اكتساب لا تحويل)،
[[salla_affiliate_channel]]، [[seo_meta_code_leak]] (نفس منطق: الكود يُستهلك بلا نقرة)،
