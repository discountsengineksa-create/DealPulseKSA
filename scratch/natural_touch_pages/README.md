# مسودات SEO — ناتشورال تاتش (ntshop.sa, master.id=74)

٣٦ مقال (٠١–٣٦) + خطة المواضيع (٠٠)، كل واحد ≥٨٠٠ كلمة محقّقة عدّاً (سكربت بايثون، مو تقدير)،
مبنية فقط على منتجات/فئات ظهرت فعلياً بسكرين شوتات الموقع الحقيقية (مو مخترعة).

**الحالة: محتوى جاهز فقط — لم يُنشر على الإنتاج.**

## ليش ما نُشرت من الجلسة اللي كتبتها؟

1. جلسة الكتابة (remote) ما عندها `DATABASE_URL`/`ADMIN_SHARED_SECRET` حقيقية أصلاً.
2. لما المالك أعطاها القيم من Railway، **classifier الأمان بهالبيئة رفض الاتصال المباشر بقاعدة الإنتاج** بمفاتيح خام.
3. حتى لو مر الحاجز: القيمة `postgres.railway.internal` عنوان داخلي بشبكة Railway فقط — ما يوصله من بيئة خارجية.
4. النشر الفعلي مو `INSERT` بسيط — يمر عبر `seo_generation_jobs` (job queue) + توليد slug فريد +
   حالة `draft→published` + `body_html_hash`، بالكود `api/seo/generator.py:413-441`. حقنها يدوياً بـSQL
   خام يتجاوز هالمنطق ويخاطر بكسر افتراضات الجدول.

## المطلوب من الجلسة اللي عندها وصول فعلي لقاعدة البيانات

لكل ملف `NN_<slug>.md` هنا (٠١–٣٦):
- العنوان = أول سطر `# ...` بالملف.
- الجسم = باقي الملف (Markdown).
- `master_id = 74` (ناتشورال تاتش)، `lang='ar'`.
- أدخليها عبر نفس مسار `seo_generation_jobs` أو دالة الإدخال بـ`api/seo/generator.py` (سطر ٤٢٢) —
  مو INSERT يدوي مباشر — عشان يتولّد الـslug والـhash صح وتوافق حالة `draft` القياسية،
  ثم مراجعة → `published` → IndexNow، بنفس بروتوكول أول ٦ صفحات (كوميت `fec8b81`).
